# AI image generation

WebAux can plan and generate a small number of contextual images during website creation. Images are stored as normal event media on the existing media volume and referenced from the visual editor with `props.mediaId`.

## Behaviour

1. The website-generation LLM returns an optional `imagePlan` (0–3 items) with the page plan.
2. If the plan is missing or invalid, a category-based fallback planner is used.
3. After the page document is installed, the generation job enters `IMAGES`.
4. Compatible OpenRouter image models are discovered from `GET /api/v1/images/models`.
5. Selection is free-first. Paid models are used only when `PRISM_IMAGE_PAID_FALLBACK_ENABLED=true` and the image fits per-image and per-website budgets.
6. Unknown pricing never unlocks a paid model.
7. Generated bytes are validated, optimised, stored under `/data/media/.../images/generated/`, and bound into IMAGE nodes.
8. Website generation still completes when image generation is skipped or fails.

## Configuration

| Variable | Default | Meaning |
|----------|---------|---------|
| `PRISM_IMAGE_GENERATION_ENABLED` | `false` | Master switch |
| `PRISM_IMAGE_PROVIDER` | `openrouter` | Provider id |
| `PRISM_IMAGE_FREE_FIRST` | `true` | Prefer free models |
| `PRISM_IMAGE_PAID_FALLBACK_ENABLED` | `false` | Allow paid models |
| `PRISM_IMAGE_MAX_IMAGES_PER_WEBSITE` | `3` | Cap |
| `PRISM_IMAGE_MAX_COST_PER_IMAGE_USD` | `0.05` | Per-image budget |
| `PRISM_IMAGE_MAX_COST_PER_WEBSITE_USD` | `0.15` | Per-site budget |
| `PRISM_IMAGE_MAX_RETRIES` | `2` | Provider retries |
| `PRISM_IMAGE_MODEL_CACHE_MINUTES` | `360` | Model catalogue TTL |
| `PRISM_IMAGE_WAIT_SECONDS` | `120` | Max wait during website gen |
| `PRISM_IMAGE_BASE64_ENABLED` | `false` | Optional DB Base64 copy |
| `PRISM_IMAGE_BASE64_MAX_SIZE_KB` | `2048` | Base64 size cap |
| `PRISM_IMAGE_PREFERRED_MODELS` | empty | Preferred model ids |
| `OPENROUTER_API_KEY` | empty | Shared with text generation |
| `PRISM_MEDIA_STORAGE_PATH` | `./data/media` | File root (`/data/media` in Docker) |

The app starts with image generation disabled or without an API key. Existing website generation continues to work.

## Storage

- Files: same persistent `media` Docker volume as uploads (`PRISM_MEDIA_STORAGE_PATH`).
- Metadata: `generated_assets` and `image_generation_jobs` (Flyway `V7__image_generation.sql`).
- Delivery: `/api/v1/events/{id}/media/{mediaId}` and public `/api/v1/public/media/{id}` after publish.
- Base64 is never embedded in website JSON or HTML.

## APIs

- `GET /api/v1/events/{id}/generated-assets`
- `POST /api/v1/events/{id}/generated-assets/generate`
- `POST /api/v1/events/{id}/generated-assets/{assetId}/regenerate`
- `DELETE /api/v1/events/{id}/generated-assets/{assetId}`
- `GET /api/v1/events/{id}/image-generation/jobs`
- `GET /api/v1/image-generation/models`
- `GET /api/v1/image-generation/status`
- `GET /api/v1/config/features` includes `imageGenerationEnabled`

## Troubleshooting

- No images: check `PRISM_IMAGE_GENERATION_ENABLED`, API key, and `GET /image-generation/status`.
- All skipped: no free model and paid fallback disabled, or budget too low.
- Website ready without images: expected when image generation fails or is skipped; regenerate from the visual editor.
- Coolify: keep the existing `media` volume mounted at `/data/media`. No extra volume is required.
